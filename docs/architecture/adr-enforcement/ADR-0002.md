# Enforcement plan for ADR-0002 (Hexagonal Architecture)

## Overview

This document defines the executable architecture guards for ADR-0002 and records their current
coverage in the Profile Tailors backend and shared modules.

## Changes

The observability boundary is enforced through reusable ArchUnit rules in the `shared:common` test
fixtures. Domain and application layers cannot depend on the listed observability vendor packages,
and domain code cannot depend on the `OperationalEventSink` port.

### Rules derived from the ADR

| Rule                  | Mandatory | Current enforcement      | Gap   |
|-----------------------|-----------|--------------------------|-------|
| Domain Isolation      | Yes       | HexagonalArchTest.kt     | None. |
| Application Isolation | Yes       | HexagonalArchTest.kt     | None. |
| Custom @Service Usage | Yes       | ComponentScanArchTest.kt | None. |

## Usage

Run the module architecture tests when changing layer boundaries. Modules with `domain` or
`application` packages should consume the shared observability fixture and provide their package
root; context-specific rules remain in each module.

### Proposed automated checks

### Spring Stereotype Guard

- **Mechanism**: ArchUnit.
- **Files**: `ComponentScanArchTest.kt`.
- **Expected failure**: "Application layer classes must use
  @com.profiletailors.common.domain.Service."
- **Priority**: High (Already implemented).

### Observability Vendor Guard

- **Mechanism**: ArchUnit rules shared through the `shared:common` test fixtures.
- **Files**: `server/smp/src/test/kotlin/com/profiletailors/smp/HexagonalArchTest.kt` and the
  architecture tests in `shared/storage`, `shared/presentation`, and `shared/shield/ratelimit`.
- **Rules**: `domain` and `application` do not depend on the listed SLF4J, Logback, Log4j,
  OpenTelemetry, Micrometer, `kotlinx.serialization.json`, or Jackson package namespaces; `domain`
  does not depend on `OperationalEventSink`.
- **Status**: Implemented. The reusable rule is
  `com.profiletailors.architecture.ObservabilityArchitectureRules`; module-specific layer rules
  remain unchanged.

## Troubleshooting

An architecture test failure indicates a dependency crossing the ADR-0002 boundary. Move the
framework or provider import to infrastructure, expose a framework-free port from the inward
layer, or update the owning architecture decision before changing a rule.
