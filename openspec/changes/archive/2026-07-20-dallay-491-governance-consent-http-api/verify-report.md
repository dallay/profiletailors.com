### SUGGESTION

- The trimmed task list dropped the dedicated `GetWorkspaceConsentRecordsHandlerAuthorizationTest` /
  `GetConsentHistoryHandlerAuthorizationTest` files in favor of relying on the migration +
  handler-level test. Today the authorization check inside both query handlers (`ConsentHandlers.kt`
  lines 71-76 and 86-89) is exercised only indirectly through the WebTestClient suite. A targeted
  unit test for the `AuthorizationDeniedException` path on each handler would harden the
  `workspace:consent:read` enforcement and is reasonable follow-up work but not a blocker for this
  change.
- The `validateLocale` helper checks `Locale.Builder().setLanguageTag(...).build()` membership
  against `Locale.getISOLanguages()` rather than the regex `^[a-z]{2}(?:-[A-Z]{2})?$` called out in
  `proposal.md`. Functionally equivalent for the cases tested, but the relaxed check accepts some
  well-formed but unusual tags (e.g. `en-US-x-private`). Not a defect per the trimmed task scope.
- The `WITHDRAW_ACTIVE` SQL updates the projection row in place. The append-only guarantee is held
  by `consent_record_events`, but downstream readers of `consent_records` still see the row's status
  mutate from `ACTIVE` to `WITHDRAWN`. Anyone reasoning about "append-only at the row level" should
  read the `consent_record_events` ledger instead of the projection.
